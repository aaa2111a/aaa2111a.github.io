Modulo is a collection of 50 tokens on Ethereum, distributed across ten compositional vessels that share its name. Each token is built from a single immutable seed — one number the contract computes at mint and never alters — from which its palette, speed, animation mode, and behavior layers are all derived.

The token doesn't point to an image stored somewhere else. It generates one. Every time it's called, it runs a cellular automaton from inside a self-contained HTML file that lives within the token itself, fully on-chain. The automaton operates in one of six behavioral modes, each defining how cells propagate, shift, and deform.

Some tokens carry additional layers: a bitmap system that stamps text directly into the grid, or a dither pattern that introduces a repeating structure across the surface. What the system produces feels alive — never the same frame twice, always within the same visual language. The rules are fixed. What they generate moves.

None of this depends on an external system. The rendering engine, the animation logic, the full computational apparatus — all of it is stored in Ethereum's contract layer through EthFS.

When a token is called, the contract doesn't return a URL. It builds the entire document on the fly, injecting each token's traits directly into the HTML, and returns it as a self-contained data URI that runs in the browser without a single external request.

There's no server that can go offline. No platform that can shut it down or change the rules. A call to any token will return the same engine, the same seed, the same behavior — in a year, in twenty years, under any condition short of the network itself disappearing. Permanence here isn't a promise. It's a property of how it's built.

The 50 tokens can be placed across 10 modulos by their owners — up to eight per modulo, drawn one at a time from the owner's inventory. A token can only occupy one modulo at a time, and only its owner can place or remove it.

Inside a modulo, the system reads the combined set and produces a single animation from it. Color palettes merge into a shared pool, influenced by position — tokens placed lower in the order have a stronger pull on what appears.

When multiple animation modes are present, the system cycles between them at a fixed interval, blending from one into the next. The position each token occupies isn't chosen by the owner. It's determined by rank, fixed from the moment the token was created. What enters is chosen. Where it lands was already decided.

What you hold when you own a token is a unique seed, a defined visual behavior, and the ability to decide where it goes. The token exists on its own, as a complete on-chain object, whether it's placed or not.

To settle it is to close that openness — a transaction that burns or transfers it, removing it from the arrangement permanently. What it was remains on the chain. What it was doing stops.

Contract

The ERC-721 contract is deployed on Ethereum. Each of the 50 tokens is bound to a unique seed generated at mint, from which its traits are derived deterministically and cannot be changed. The rendering engine and animation logic are stored on-chain through EthFS. A call to tokenURI() assembles the complete document on the fly — injecting that token's trait data directly into the HTML — and returns a fully self-contained data:text/html;base64. No external request, no server, no dependency. The contract handles ownership and transfer natively. It is the source of truth for what each token is and who holds it.

Interface

The web application reads state from the contract — which tokens exist, who owns them, what traits they carry. It surfaces this as an interactive environment where owners place tokens into modulos and configure which of their traits are active: which animation mode runs, at what speed, what visual size, whether the text or dither layer is on. The token defines what is possible. The owner decides what is running. Nothing is final until a token is settled. The interface is where intention is formed.

Settle

Settling is the act of commitment. When a token is settled, the owner signs a transaction that burns or transfers it — removing it from circulation permanently. The traits that defined its visual identity are on-chain from mint and remain there. What ends is the token's presence in the system: it can no longer be placed, configured, or composed. The arrangement closes not because it was recorded, but because the token is gone. It cannot be undone.
